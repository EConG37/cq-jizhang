# 文字收入及备用补记

截图快捷指令默认收支类型=支出，不通过对话逐笔确认截图。收入让用户单独告诉Agent，例如“今天收到工资5000元”“记一笔收入：昨天兼职300元”。

明确记账意图＋金额/类型/项目足够时，视作授权新增，直接写一次，不额外要求“确认”。“下周可能收到5000元”“每周预算800元”“如果收到工资”都不创建实际账单。金额或收支方向不明时只问必要缺项。

从消息提取金额（有效正数）、收入或支出、具体项目、日期。没说日期用当前用户时区时间，并在结果显示；明确历史日期按该日期写时间戳，不假称截图日期是发生日期。只有日期没时间时用当地00:00并显示日期，不编造具体时刻。

写“具体开支”原六列：文本内容保留用户原话，收支类型显式“收入”，金额、具体花费项目按实际可写字段写入。原v1可写日期用毫秒时间戳；CLI Base v3按schema用日期字符串，自动创建时间等只读字段不提交。模板日期若为只读创建时间，历史补记不能声称已经保存真实历史发生日期，需核对字段配置后再报告。消费类型本身为支出分类，收入可留空，统计时收入不进消费类别也不抵扣预算，不增加“工资”支出分类。

CLI模式按 [当前Agent接入](agent-cli.md) 的实际命令与CellValue协议写入：单选收支类型用["收入"]，外层新增用当前版本+record-batch-create支持的create_records，不照抄旧v1 fields。原记录OCR补全仍使用update_records，不能用新增命令代替。读取单选经适配后再验收金额和收支类型。

先读取实际schema决定可写字段；AI字段若允许明确值写入则写，若只能触发则提交明确收入文本＋收入类型并读回AI结果。因收入默认提取提示只懂支出而金额/项目错，指导调整该副本对应AI提取提示以支持收支双方；没有修改权限就让用户操作。不强制重建字段，保留六列布局。

只有目标record_id、收入类型及金额读回符合输入才能说“已记录收入”；AI等待时说“文本已保存，金额待核对”。需要用户手动修改该原记录时给具体位置。写入不确定先查询，不能无条件重试造成双账。

成功简短回复：“已记录收入：10月13日｜工资｜5000元。收入单独统计，不抵扣本周消费预算。”使用实际日期，不照抄示例。修改历史记录先定位并展示差异后确认，不从闲聊推断授权。
